# Active Directory

Интеграция необязательна. Пустой `AD_LDAP_URI` (в `install/.env` и `backend/.env`) выключает её целиком:
админы входят по локальным паролям, ящики только `auth = local`, в Dovecot нет `passdb ldap`, таймер
синхронизации не включается, фронт прячет разделы AD (по `GET /auth/config`).

## Что даёт

| Где | Как работает |
|---|---|
| Вход в панель | Админ заведён `admin-add user@corp.local superadmin` без пароля → бэкенд делает bind в AD под его UPN. Логины `user`, `CORP\user`, `user@corp.local` приводятся к UPN (`AD_UPN_SUFFIX`, `AD_NETBIOS`). Отключённая в AD учётка не входит |
| Пароль ящика `auth = ad` | Dovecot: `passdb sql` отдаёт `noauthenticate` для таких ящиков → `passdb ldap` ищет учётку, у которой `userPrincipalName` или `mail` равен адресу, и делает bind её паролем. Ящик обязан существовать в базе (userdb), иначе входа нет даже с верным паролем |
| Синхронизация (раз в час и кнопкой в панели) | Учётки с атрибутом `mail` в активных доменах сервера → ящики `auth = ad` (квота — по умолчанию домена); отключённые или пропавшие → `active = false` (только для `auth = ad`); рассылки с заданной группой (DN) → состав из участников группы с вложенностью. Без `--apply` — предпросмотр |
| Личный кабинет | Пользователь `auth = ad` входит паролем AD; смена пароля — в AD, кабинет об этом сообщает |

Локальные ящики (`auth = local`) и AD-ящики живут вместе; неверный локальный пароль **не** проваливается в AD
(иначе пароль доменной учётки с тем же именем открывал бы чужой локальный ящик).

## Что нужно от домена

1. **Сервисная учётка** только для чтения (`AD_BIND_USER`, `AD_BIND_PASSWORD`): поиск пользователей и групп.
   Пароль не должен истекать; интерактивный вход ей не нужен.
2. **LDAPS.** Без TLS пароли пользователей идут на DC открытым текстом. Контроллеру нужен сертификат с EKU
   «Проверка подлинности сервера» и SAN с его FQDN. Если в домене нет AD CS, самоподписанный выпускает
   `tools/ad-ldaps-cert.ps1` (запуск на DC от администратора; печатает PEM открытой части). Этот PEM кладут в
   `install/certs/ad-ca.pem` (`AD_CA_CERT`): `install.sh` добавит его в доверенные ОС и остановится, если
   `openssl s_client -verify_hostname` не подтверждает соединение. Доверия «при первом обращении» нет.
3. **Global Catalog**: `AD_LDAP_URI=ldaps://dc.corp.local:3269` (3268 без TLS). На обычных 389/636 лес с дочерними
   доменами отдаёт referrals, и `libldap` в Dovecot на них зависает.
4. **DNS**: имя DC должно резолвиться на почтовом сервере. Локальный unbound валидирует DNSSEC, поэтому внутреннюю
   зону форвардят на DNS домена без проверки: `AD_DNS_ZONE=corp.local`, `AD_FORWARD_DNS=<ip DC>`,
   при необходимости `AD_REVERSE_ZONES="10.in-addr.arpa"`.
5. Сетевой доступ с почтового сервера к DC: 3269/tcp (или 636), 53/udp+tcp.

Проверка на сервере:

```bash
openssl s_client -connect dc.corp.local:3269 -verify_hostname dc.corp.local </dev/null | grep "Verify return"
ldapsearch -H ldaps://dc.corp.local:3269 -D svc@corp.local -w '…' -b DC=corp,DC=local '(mail=user@example.com)' mail userPrincipalName
doveadm auth test user@example.com      # пароль AD
```

## Привязка и права

- Какие учётки станут ящиками, решает атрибут `mail`: домен адреса должен быть среди активных доменов сервера.
  Кто умеет писать `mail` в AD, тот управляет адресами — это нужно учитывать в делегировании AD
  (синхронизация переписывает `ad_upn` по `mail`; привязка по `objectGUID` — в планах, см. `security.md`).
- Группа для рассылки указывается DN (`CN=Staff,OU=Groups,DC=corp,DC=local`); участники — пользователи с `mail`,
  вложенные группы раскрываются (`LDAP_MATCHING_RULE_IN_CHAIN`). Пока группа задана, состав из панели не правится.
- Администраторов панели AD не назначает: роль — в таблице `admins` (`admin-add`), AD только проверяет пароль.

## Перебор паролей

Каждая попытка входа в панель или кабинет — bind в AD, а значит, при политике блокировки учёток перебор
снаружи может блокировать доменные аккаунты. Поэтому бэкенд считает неудачи в Redis (5 по логину и 20 по IP за
15 минут → 429 до обращения к AD), а nginx ограничивает `/auth/login` и `/me/login` до 10 запросов в минуту с адреса.
IMAP/SMTP (993/587/465) проверяют пароли AD-ящиков напрямую через Dovecot: там работают `auth_failure_delay`
и fail2ban (5 попыток / 10 минут → бан на час), но распределённый подбор они не остановят. Варианты для
строгих сред: AD-ящики только из своих сетей, отдельные пароли приложений для внешнего доступа (локальные
хеши), smart lockout на стороне DC.

## Сертификат DC: обновление и запасной контроллер

`tools/ad-ldaps-cert.ps1` при повторном запуске ничего не делает, пока действующий сертификат годен ещё 30 дней;
ближе к сроку выпускает новый — тогда обновите `install/certs/ad-ca.pem` и выполните `install.sh`. На каждый DC,
который будет в `AD_LDAP_URI`, сертификат выпускается отдельно; в `AD_CA_CERT` можно положить несколько PEM
подряд (один файл).
