# Безопасность

Как сообщить об уязвимости — [`SECURITY.md`](../SECURITY.md) в корне.

## Модель

Почтовый сервер стоит одним хостом наружу (25/465/587/993) и держит панель управления для своих сетей.
Угрозы, от которых проект защищается в первую очередь:

1. **Компрометация панели** (уязвимость в бэкенде/фронте, украденный токен, злой доменный админ) не должна
   превращаться в шелл на хосте, чтение чужой почты или открытый релей.
2. **Компрометация почтового демона** (Postfix, Dovecot, Rspamd) не должна давать хеши паролей и ключи DKIM.
3. **Перебор паролей** снаружи не должен блокировать доменные учётки и подбирать ящики.
4. **Взломанный ящик** не должен становиться рассыльщиком спама.

## Границы доверия

| Компонент | Может | Не может |
|---|---|---|
| Бэкенд (`mailapp`) | читать/писать таблицы базы `mail`, класть ключи DKIM в Redis, спрашивать агента, bind в AD, ManageSieve с localhost | читать файлы хоста, запускать команды, менять конфиги, писать в свой код (он принадлежит root) |
| Агент (`mailagent`) | команды из `install/sudoers-mail-agent` с аргументами по регулярным выражениям sudo | что-либо ещё; клиент передаёт только id письма и значения параметров из белого списка |
| Postfix (`mail_postfix`) | `SELECT` из `v_postfix_*` | таблицы, хеши паролей, ключи DKIM |
| Dovecot (`mail_dovecot`) | `SELECT` из `v_dovecot_*` (хеш только своего ящика при входе) | таблицы, ключи DKIM, пароли чужих объектов |
| Rspamd | Redis (байес, DKIM-ключи, история), карты в `/var/lib/rspamd/maps` | база |
| Фронт | `/api` с JWT | — |
| Веб-почта (отдельный хост) | IMAP/SMTP/ManageSieve как обычный клиент | база, API, хост |

Компрометация панели даёт запись в базу почтовых объектов (серьёзно, но обратимо и видно в `audit_log`,
куда бэкенд может только добавлять), а не шелл. Панель и интерфейс Rspamd наружу не публикуются вообще.

## Что сделано

**Хост и службы**
- nftables: снаружи только 25/465/587/993 и 80 (ACME, редирект); 443, 4190, 22, 10050 — из `LAN_NETS`.
- sshd drop-in: только ключи, без root, без X11/agent/tcp forwarding, 3 попытки.
- systemd-песочницы: бэкенд без capabilities, `SystemCallFilter=@system-service`, только AF_INET/INET6/UNIX,
  `ProtectSystem=strict`, `UMask=0077` (оценка `systemd-analyze security` ≈ 1.3); агент — то же, кроме
  необходимого для sudo и `AF_NETLINK` для `postqueue`.
- Код и venv бэкенда принадлежат root; `backend/.env` 0640 root:mailapp; `install/` 0700 root (там пароли
  ролей и ключ сертификата); журналы Postfix/Dovecot 0640 root:adm; `render.py` пишет с umask 077.
- LLMNR/mDNS выключены; unbound только на localhost; Redis с паролем, только localhost.
- sudoers агента — регулярные выражения `^…$` (sudo ≥ 1.9.10), файл проверяется `visudo -cf` до установки;
  root-помощник `apply_settings.py` сам валидирует ключи и значения (`mynetworks` — только частные сети не
  шире /16 и loopback; TLS-протоколы — перечень; текст квоты — белый список символов).

**Почта**
- Нет открытого релея: отправка только с авторизацией, `reject_authenticated_sender_login_mismatch`,
  VRFY выключен, TLS ≥ 1.2, SASL к smarthost только с TLS (`noanonymous, noplaintext`).
- `milter_default_action = tempfail`: при недоступном Rspamd письма ждут, а не проходят без проверки.
- Catch-all не перехватывает существующие ящики (в `v_postfix_aliases` есть строки «ящик → сам себе»);
  smarthost не перехватывает входящую на свои домены (явные транспорты `lmtp:`).
- Лимиты: не более 10 целей пересылки у пользователя, 100 у алиаса; Rspamd `ratelimit` 500 писем/час на
  аутентифицированного пользователя; Sieve `max_redirects = 4`, `max_actions = 32`.
- Master-пользователь ManageSieve `panel` принимается только с 127.0.0.1 (`allow_nets`).
- Dovecot: неверный локальный пароль не проваливается в AD; логина нет в базе — отказ до обращения к AD.
- DANE для исходящих (локальный DNSSEC-резолвер), ARC и DKIM подписи, DMARC-проверка.

**Панель и API**
- JWT HS256 с обязательным секретом ≥ 32 символов (иначе бэкенд не стартует), TTL 120 минут; Swagger/OpenAPI
  отключены; все SQL параметризованы, LDAP-фильтры экранируются; ответы API без хешей и приватных ключей;
  во фронте нет `v-html`.
- Защита входа: счётчики неудач в Redis по логину (5) и IP (20) за 15 минут → 429 **до** обращения к AD;
  `limit_req` 10 r/min на `/auth/login` и `/me/login` в nginx; фиктивная проверка bcrypt для неизвестного
  логина/адреса (одинаковое время ответа).
- Пароли: bcrypt cost 12 (`{BLF-CRYPT}`, понятен Dovecot); импортированные `{SSHA512}` перехешируются при
  входе; смена пароля в кабинете требует текущий; у админов — локальный хеш или bind в AD.
- Роли проверяются на каждом роутере (доменный админ видит только свои домены); журнал аудита с IP.
- Заголовки nginx: HSTS, `X-Frame-Options DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`,
  CSP (`default-src 'self'`, `frame-ancestors 'none'`, `base-uri 'none'`, `form-action 'self'`).

**Репозиторий**
- Секреты только в `.env` (в git нет); pre-commit `tools/check_secrets.py` ищет значения из `.env`, приватные
  ключи, токены; CI проверяет все файлы. Сертификат DC не хранится в репозитории (`install/certs/`).

## Известные ограничения

Решения, которые не приняты за проект и остаются на усмотрение администратора:

1. **Перебор паролей AD-ящиков через IMAP/SMTP.** Защищают `auth_failure_delay` и fail2ban (по IP), но не от
   распределённого подбора и блокировок учёток в AD. Варианты: AD-ящики только из своих сетей, пароли приложений
   для внешнего доступа, smart lockout на DC. См. `active-directory.md`.
2. **Подделка заголовка `From`** аутентифицированным пользователем внутри своего домена: envelope проверяется
   (`sender_login_maps`), заголовок — нет. Нужно правило Rspamd «From ∈ адресам пользователя».
3. **Привязка AD-ящика по атрибуту `mail`**: кто умеет писать `mail` в AD, может «забрать» ящик при следующей
   синхронизации. Планируется привязка по `objectGUID` с ручным подтверждением смены.
4. **Режимы `internal` / `receive_only` обходятся пересылкой или Sieve-редиректом** (локальная отправка минует
   smtpd-ограничения). Нужен запрет внешних целей для таких ящиков.
5. **`local_addrs` Rspamd = `LAN_NETS`**: письма из своих сетей не проходят SPF/DMARC/RBL и получают DKIM-подпись.
   Удобно для внутренних систем, но доверяет всей сети; при необходимости — перечень конкретных источников.
6. **Throttle по логину** позволяет любому из разрешённой сети временно заблокировать вход конкретному админу
   (цена защиты учётки AD от lockout).
7. **Токен в `localStorage`**; интерфейс Rspamd на том же origin (`/rspamd/`): XSS в стороннем UI читал бы токен.
   Варианты: Rspamd на отдельном имени или HttpOnly-cookie.
8. **Антивирус fail-open**: при недоступном clamd письма проходят без проверки (но Rspamd-проверки остаются).
9. **Зависимости**: прямые версии закреплены, транзитивные — нет; `pip-audit`/`npm audit` в CI не запущены.
10. **`reject_unknown_reverse_client_hostname` на 25** отклоняет (450) отправителей без PTR. Строгая политика,
    отсекает много спама, но и часть легитимных серверов с кривым DNS; альтернатива — отдать скоринг Rspamd.
11. **Один хост**: нет отказоустойчивости; бэкап и мониторинг — внешними средствами (`operations.md`).
