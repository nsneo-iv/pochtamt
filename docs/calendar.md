# Календарь, контакты, ActiveSync: SOGo

Необязательный компонент. SOGo добавляет к почте то, чего у Dovecot нет: CalDAV и CardDAV с приглашениями на
встречи и ответами на них, занятость коллег, общие календари и адресные книги с правами, напоминания по почте,
собственную веб-почту и ActiveSync (Exchange-протокол) для Outlook и телефонов без дополнительных программ.

Ставится на тот же хост, в Docker: образ собирается прямо на сервере из пакета `sogo` того же Debian 13,
контейнер работает в сети хоста и слушает только `127.0.0.1:20000`, наружу его публикует nginx хоста.
Пользователи входят адресом ящика и паролем, локальным или из Active Directory.

## Включение

1. DNS: A-запись `SOGO_HOSTNAME` (например `groupware.example.com`) на внешний адрес сервера. Имя должно
   отличаться от `ADMIN_HOSTNAME`. При certbot оно автоматически попадёт в сертификат; при сертификате с другого
   хоста оно должно быть в нём (wildcard подходит).
2. `install/.env`:
   ```
   SOGO_HOSTNAME=groupware.example.com
   DB_SOGO_PASSWORD=<openssl rand -hex 24>
   SOGO_TIMEZONE=Europe/Moscow
   SOGO_WORKERS=5              # по одному на устройство с push ActiveSync + запас для веба
   DOCKER_REGISTRY_MIRRORS=    # зеркала Docker Hub, если он недоступен напрямую
   ```
3. `bash install/install.sh` (или `deploy.sh`). Скрипт поставит `docker.io` и `docker-compose`, выключит у Docker
   управление iptables, создаст роль и базу `sogo`, соберёт образ (несколько минут), включит службу `sogo`,
   сайт nginx и откроет 443 для всех (панель остаётся закрытой allow-списком).
4. Памяти хосту нужно на ~1 ГБ больше: 6 ГБ для VM с ClamAV и SOGo.

Проверка: `systemctl status sogo`, `journalctl -u sogo -n 50`, `curl -I https://groupware.example.com/SOGo/`
(302 на страницу входа), вход в вебе адресом ящика.

Выключение: очистить `SOGO_HOSTNAME`, повторить `install.sh` — служба и сайт удаляются, база `sogo`, образ
и Docker остаются (удалить вручную: `dropdb sogo`, `docker image rm pochtamt/sogo:debian13`, `apt purge docker.io`).

## Как это устроено

| Что | Как |
|---|---|
| Пользователи | источник SQL: представление `v_sogo_users` в базе `mail` (активные локальные ящики, хеши `{BLF-CRYPT}` проверяет SOGo); при AD — второй источник LDAP (учётки с `mail`, bind паролем пользователя). Оба источника видны как адресные книги «Сотрудники» и «Active Directory» |
| Почта | IMAP `127.0.0.1:143` (слушатель только на loopback, появляется вместе с SOGo), отправка через submission 587 с авторизацией пользователя: Postfix проверяет, что адрес его, Rspamd подписывает DKIM и считает лимиты, как для любого клиента |
| База SOGo | PostgreSQL хоста, база `sogo` (профили, календари, контакты, сессии), роль `sogo` |
| Сессии и кэш | memcached внутри контейнера на loopback |
| Напоминания | `sogo-ealarms-notify` раз в минуту внутри контейнера; письма уходят через 587 |
| Логи | `journalctl -u sogo` (вывод контейнера), nginx `/var/log/nginx/` |
| Файлы на хосте | `/etc/sogo/` (конфиг 0640 root:950, compose, контекст сборки), `/var/lib/sogo/data`, `/var/lib/sogo/www` (статика для nginx) |

Что в SOGo выключено намеренно: автоответ, пересылка, фильтры (ими управляет панель через Sieve, иначе два
источника правды перезаписывали бы скрипт пользователя), смена пароля (в личном кабинете `/me` или в AD),
дополнительные почтовые аккаунты, публичный доступ к календарям без входа.

Видимость по умолчанию: коллеги видят занятость (даты и время событий, не содержание), пользователь меняет это в
настройках календаря. Приглашения уходят письмом, ответы обрабатываются SOGo; внешние участники получают обычное
письмо с `.ics`.

## Клиенты

| Клиент | Как подключить |
|---|---|
| Веб | `https://groupware.example.com/` — почта, календарь, контакты, настройки |
| iPhone / iPad, macOS | «Учётные записи → Exchange»: адрес, пароль, сервер `groupware.example.com` (ActiveSync: почта, календарь, контакты, push). Либо CalDAV/CardDAV: сервер `groupware.example.com`, автонастройка через `.well-known` |
| Android | Exchange-аккаунт в стандартной почте (ActiveSync) или DAVx⁵ с базовым адресом `https://groupware.example.com/SOGo/dav/` |
| Outlook (Windows) | Exchange ActiveSync не поддерживается новыми версиями Outlook для ПК; используйте CalDAV Synchronizer (бесплатный плагин) с адресом `https://groupware.example.com/SOGo/dav/<адрес>/` или веб |
| Thunderbird | Календарь: новый сетевой календарь, адрес `https://groupware.example.com/SOGo/dav/<адрес>/Calendar/personal/`; контакты: CardDAV `https://groupware.example.com/SOGo/dav/<адрес>/Contacts/personal/`. Плагин TbSync тоже умеет |
| Любой CalDAV/CardDAV | `https://groupware.example.com/SOGo/dav/`, логин — адрес ящика |

ActiveSync держит соединение до часа (push); на каждое такое устройство нужен воркер `sogod`
(`SOGO_WORKERS`). Если устройств много, поднимите число воркеров и память.

## Эксплуатация

- **Обновление**: `install.sh` пересобирает образ с `--pull` (свежие пакеты Debian внутри) и перезапускает
  службу. Обновления безопасности SOGo приходят через `security.debian.org` в пакете `sogo` при следующей сборке,
  поэтому `install.sh` стоит запускать регулярно (раз в месяц) или после объявлений Debian.
- **Бэкап**: `pg_dump -Fc sogo` вместе с базой `mail` (там же все календари и контакты); `/var/lib/sogo/data`
  содержит только служебный профиль GNUstep и восстанавливается сам.
- **Отладка входа**: `journalctl -u sogo | grep -i "login\|auth"`; для AD — `docs/active-directory.md`; для
  локальных ящиков убедитесь, что `SELECT c_uid FROM v_sogo_users` под ролью `sogo` возвращает адрес.
- **Отладка отправки**: в логе Postfix `postfix/submission` с `sasl_username=` пользователя; отказ `553 Sender
  address rejected` означает, что адрес отправителя не принадлежит пользователю.
- SOGo блокирует пользователя на 5 минут после 5 неудачных входов за минуту (`SOGoMaximumFailedLoginCount`);
  fail2ban nginx для SOGo не настроен, защита от перебора остаётся на стороне SOGo и Dovecot.

## Безопасность

SOGo получает пароль пользователя (как любой веб-клиент) и читает хеши паролей локальных ящиков из
`v_sogo_users`, чтобы проверять их самостоятельно. Компрометация контейнера даёт эти хеши (bcrypt cost 12) и
доступ к почте активных пользователей через их сессии, но не к базе `mail` на запись, панели и хосту:
контейнер без capabilities, с `no-new-privileges`, конфиг только на чтение, процессы от непривилегированного
пользователя. Подробнее о границах доверия — `security.md`.
