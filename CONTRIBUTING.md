# Как участвовать

Спасибо, что хотите помочь. Правила короткие, но их стоит прочитать до первого коммита.

## Язык

Документация, комментарии, докстринги, `.env.example` и тексты интерфейса — на русском. Код, имена ключей
конфигурации и API — на английском. Сообщения коммитов — на русском, одной строкой «что сделано», при
необходимости с подробностями ниже.

## Где что лежит

Архитектура и границы доверия — [`docs/architecture.md`](docs/architecture.md), контракт API —
[`docs/api.md`](docs/api.md). У каждой папки есть README с таблицей файлов: добавили файл — допишите строку.

## Правила, которые нельзя нарушать

1. **Бэкенд не ходит на хост.** Он пишет только в PostgreSQL и Redis. Всё, что требует команд на хосте, идёт через
   `agent/` с белым списком в sudoers (`install/sudoers-mail-agent`). Не добавляйте бэкенду доступ к файлам,
   шеллу или новым сокетам.
2. **Postfix и Dovecot читают только представления** `v_postfix_*` / `v_dovecot_*` под ролями `mail_postfix` /
   `mail_dovecot`. Меняете схему — сохраняйте контракт представлений, а не правьте конфиги демонов.
3. **Секретов в git нет.** Пароли, токены, ключи — только в `.env` своей папки (`install/`, `backend/`, `agent/`,
   `frontend/`). Новый ключ → в `.env.example` этой папки с комментарием, что это и где взять. Перед коммитом
   работает `tools/check_secrets.py` (ставится один раз: `python tools/check_secrets.py --install`); если он
   сработал — вынесите значение в `.env`, а не обходите проверку.
4. **Шаблоны конфигов** содержат плейсхолдеры `@KEY@`; новый ключ → `install/.env.example` и, если это новый
   файл, список `TEMPLATES` в `install/render.py`. `python install/render.py --check` должен проходить.
5. **Меняете API — правьте `docs/api.md` и фронт в одном коммите.**
6. **Белые списки параметров** сервера (`backend/app/services/hostconf.py` и `agent/apply_settings.py`) —
   одинаковые в обоих местах; новое значение должно валидироваться и там, и там.

## Окружение разработчика

```bash
# бэкенд
cd backend && python -m venv .venv && . .venv/bin/activate && pip install -e ".[dev]"
ruff check app tests && pytest -q
# агент
pytest -q agent/tests
# фронт
cd frontend && npm ci && npm run typecheck && npm run build
# шаблоны
python install/render.py --check          # нужен install/.env (можно из .env.example с заглушками)
```

Python 3.11+, ruff (120 символов в строке). Фронт — Vue 3 + TypeScript + PrimeVue, версии в `package.json`
зафиксированы точно. `.sh` — только с LF (`.gitattributes`), `.ps1` — UTF-8 с BOM и CRLF.

Конфиги Dovecot — версии 2.4 (Debian 13): синтаксис отличается от 2.3, после правок шаблона проверяйте
`doveconf -n` на стенде.

## Как предложить изменение

1. Issue с описанием проблемы или идеи (для правок в пару строк можно сразу pull/merge request).
2. Ветка от `main`, один логический коммит на одну задачу.
3. CI (`.github/workflows/ci.yml`, `.gitlab-ci.yml`) должен быть зелёным: проверка секретов, ruff, pytest,
   `render.py --check`, `vue-tsc` и сборка фронта.
4. Для изменений в установке — прогон `install/install.sh` на чистой VM Debian 13 (повторный запуск тоже должен
   проходить: скрипт идемпотентен).
