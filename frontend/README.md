# Фронтенд панели администрирования почты

Одностраничное приложение на Vue 3 + TypeScript + Vite, компоненты PrimeVue 4 (тема Aura).
Работает поверх REST API бэкенда по контракту `docs/api.md` (префикс `/api/v1`, JWT в `Authorization: Bearer`).

## Запуск в режиме разработки

```bash
cd frontend
npm install          # ставит версии строго по package-lock.json
npm run dev          # http://localhost:5173
```

Dev-сервер проксирует все запросы к `/api` на бэкенд `http://127.0.0.1:8000` (см. `vite.config.ts`),
поэтому бэкенд должен быть запущен локально на 8000 порту. Переменные окружения — в `.env`
(образец `.env.example`); по умолчанию `VITE_API_BASE` пустой, то есть API берётся с того же origin.

## Сборка

```bash
npm run build        # проверка типов (vue-tsc) + сборка Vite
npm run typecheck    # только проверка типов
npm run preview      # локально посмотреть собранный dist
```

Результат сборки кладётся в `frontend/dist/` (каталог исключён из git). Его отдаёт nginx как статику:
корень сайта → `dist/`, для всех путей, кроме `/api/` и `/rspamd/`, нужен `try_files $uri /index.html`
(история маршрутов HTML5), `/api/` проксируется на бэкенд, `/rspamd/` — на веб-интерфейс Rspamd
(ссылка на него есть на сводке). Конфиг nginx живёт в `install/nginx/`.

Название панели (шапка, вход, заголовок вкладки) — `VITE_APP_TITLE` (по умолчанию «Почтамт»), ссылка на
веб-почту в кабинете — `VITE_WEBMAIL_URL`; оба — в `.env` при сборке, читаются в `src/brand.ts`.

## Структура

```
src/
  brand.ts      название панели и адрес веб-почты из переменных сборки
  api/          клиент (fetch + Bearer, 401 → разлогин, разбор {detail}) и функции на каждый эндпоинт
    types.ts    типы всех объектов контракта
  stores/auth   pinia-стор админа: токен в localStorage, пользователь, роль, возможности сервера (/auth/config)
  stores/me     pinia-стор личного кабинета: свой токен и карточка пользователя
  stores/theme  режим темы (светлая / тёмная / как в системе), класс .app-dark на <html>
  router/       маршруты, guard авторизации и ролей, стартовая страница по роли, ветка /me/*
  layouts/      MainLayout (админка, левое меню) и MeLayout (личный кабинет)
  components/   ThemeSwitch, RspamdStatsCards, SystemChart (Chart.js с цветами темы),
                settings/ — формы автоответа, пересылки, Sieve, настроек домена
  pages/        страницы (ниже); pages/filter/ — вкладки фильтра, pages/server/ — вкладки сервера, pages/me/ — кабинет
  composables/  useNotify (Toast + ConfirmDialog), useDomains (список доменов),
                useDomainQueryFilter (фильтр по домену, синхронизированный с ?domain=)
  utils/        форматирование объёмов, дат и аптайма, проверки адресов, буфер обмена
  locale/ru.ts  русская локаль PrimeVue
```

## Страницы

| Путь | Что делает | Роли |
|---|---|---|
| `/login` | Вход админа: локальный пароль или доменная учётка AD (`POST /auth/login`); подсказка логина из `GET /auth/config` | — |
| `/dashboard` | Общая сводка: домены, ящики, алиасы, рассылки, очередь, занятое место (`GET /stats`); блок «Антиспам и антивирус» из `stats.rspamd` со ссылкой на `/rspamd/` | superadmin (domain_admin переадресуется на дашборд своего домена) |
| `/domains` | Таблица доменов (имя — ссылка на дашборд), создание/редактирование, сведения со статистикой, DKIM-ключ в диалоге | все (создание и удаление — superadmin) |
| `/domains/:name` | Дашборд домена (`GET /domains/{name}/dashboard`): статистика, проверка DNS MX/SPF/DKIM/DMARC с ожидаемыми записями и копированием, DKIM-ключ (создать/удалить), топ-10 ящиков по месту, последние действия; кнопки «Ящики/Алиасы/Рассылки» открывают списки с фильтром по домену; переключатель домена, если доменов больше одного | все |
| `/mailboxes` | Ящики: фильтр по домену (`?domain=`) и поиску (`?q=`), создание с выбором авторизации local/AD, редактирование, квота, активность, смена пароля (только local) | все |
| `/aliases` | Алиасы и пересылки (`?domain=`), включая catch-all `@domain`; получатели — список чипов | все |
| `/domain-aliases` | Доменные алиасы: создание и удаление | superadmin |
| `/lists` | Рассылки (`?domain=`): участники чипами; при заданной группе AD состав только для чтения | все |
| `/mailboxes/:address/settings` | Настройки ящика: режим (обычный / только приём / только отправка / только внутрь), автоответ с датами, пересылка с копией, BCC, пользовательские правила Sieve; в PUT уходят только изменённые секции, 422 по Sieve — под полем, `sieve_error` — предупреждение | все |
| `/queue` | Очередь Postfix: таблица, повторная отправка всей очереди, удаление письма | superadmin |
| `/system` | Состояние сервера (`/system/overview`, автообновление 30 с): плитки CPU / память / диски / аптайм / сертификат / очередь / сессии IMAP / база / Redis, службы тегами, почта за сутки и баны fail2ban, счётчики Rspamd; графики истории (`/system/history`, период 6 ч / 24 ч / 7 дней, Chart.js через PrimeVue Chart, цвета из переменных темы): нагрузка, память, диски, очередь, почта в час, сессии IMAP | superadmin |
| `/server` | Настройки сервера, вкладки: «Исходящая почта» (smarthost, пароль отправляется только если введён), «TLS к получателям» (политики по доменам), «Доступ SMTP» (правила client/sender/recipient → OK/REJECT/DISCARD), «Параметры» (белый список параметров Postfix/Dovecot по группам, применяются сразу с перезагрузкой службы, 422 — у поля) | superadmin |
| `/filter` | Спам-фильтр и антивирус (Rspamd + ClamAV), вкладки: «Сводка» (счётчики, пороги, состояние антивируса, запрос обновления баз), «Пороги» (greylist / add_header / reject с проверкой возрастания), «Списки» (белые и чёрные списки адресов и IP чипами), «История» (проверенные письма с фильтрами, раскрытием символов и автообновлением раз в 30 с), «Символы» (веса с inline-редактированием, сохраняются только изменённые) | superadmin |
| `/audit` | Журнал аудита с серверной пагинацией и фильтрами по актору и объекту | все |
| `/ad-sync` | Синхронизация с AD: предпросмотр изменений → применить; пункт скрыт, если AD не настроен (`ad_enabled` из `/auth/config`) | superadmin |

На дашборде домена есть карточка «Настройки домена» (`/domains/{name}/settings`: transport, BCC, внешняя исходящая
почта); сохранять может только superadmin, domain_admin видит значения без кнопки.

Стартовая страница после входа: для superadmin — `/dashboard`, для domain_admin — дашборд его первого домена.
Для `domain_admin` пункты `/domain-aliases`, `/queue`, `/ad-sync` скрыты из меню, а переход по прямой ссылке
уводит на стартовую. Удаления подтверждаются через ConfirmDialog, ошибки API показываются в Toast.

## Личный кабинет пользователя (`/me/*`)

Отдельное дерево маршрутов со своим лейаутом (`layouts/MeLayout.vue`: шапка с адресом, переключатель темы, выход)
и своим стором `stores/me.ts` — токен кабинета (`typ=user`) хранится под ключом `pochtamt.me.token`, отдельно
от админского. Клиент API общий: для путей `/me/*` Bearer берётся из стора кабинета, 401 ведёт на `/me/login`.
Кабинет не делает ни одного админского запроса и работает для обычных пользователей.

| Путь | Что делает |
|---|---|
| `/me/login` | Вход по адресу ящика и паролю (`POST /me/login`) |
| `/me` | Карточка ящика (адрес, имя, занято/квота, писем, режим), смена пароля (только `auth=local`, иначе подсказка про AD), автоответ, пересылка, правила Sieve (`PUT /me/settings`, только изменённые секции), ссылка на веб-почту (`VITE_WEBMAIL_URL`) |

Формы автоответа, пересылки и Sieve общие с админскими настройками ящика: `components/settings/`.

## Темы оформления

Переключатель (солнце / луна / монитор) в нижней части меню и на странице входа. Три режима: светлая, тёмная,
как в системе (`prefers-color-scheme`, по умолчанию). Выбор хранится в `localStorage` (`pochtamt.theme`).
Тёмная тема включается классом `app-dark` на `<html>` — он же указан как `darkModeSelector` в настройках
PrimeVue. Свои стили в `src/assets/main.css` используют токены PrimeVue (`--p-text-color`, `--p-content-background`,
`--p-surface-*`) и переменные `--app-*`, переопределённые для `:root.app-dark`, — цвета не хардкодятся.

## Версии

Все версии в `package.json` зафиксированы точно (без `^`); обновлять через `npm install <пакет>@<версия> --save-exact`.
